# CL Prompt Enhancer (GGUF)

Prompt Merger等のグローバル縮小Markdownへ、外部画風、背景密度、人物動作及びカメラワークのプロファイルを適用します。Subject、保持分析、Markdown構造及び固定プロファイル文の挿入はPythonが管理します。

```text
Prompt Merger.merged_markdown ──> source_markdown ┐
ユーザー最終指示 ───────────────> user_prompt     ├─> enhanced_markdown
Connected Combo ────────────────> 各override ─────┘
```

## 画風と背景

`style_profile`には年代別アニメ、映画実写、写真実写、各種スケッチ、水彩画、イラスト、マスターピース及び`passthrough`があります。アニメ系は人物のキーポーズ、二コマ／三コマ打ち及び限定的な中割りによる手描きリミテッドアニメを肯定形で指定します。ポーズの保持から次の動作への進行、歩行時の接地、指定されたSource Vocalへの口形同期も明記します。

`background_detail`は`reduce`、`low`、`medium`、`high`、`ultra`、`passthrough`です。プロファイルは`node_prompt_enhancer/prompts/`以下のmanifestから検出します。

## 人物動作とカメラ

`motion_profile`は`subtle`、`natural`、`dynamic`、`music_video`、`mv_anime_emotional`、`limited_anime`及び`passthrough`です。動作段階、接地、重心移動、付属物の追従、歌詞への反応及びリップシンクを、ユーザーが毎回長文で記述しなくてもCommonへ追加できます。

`camera_profile`は`stable`、`cinematic`、`dynamic`、`orbit_subject`、`mv_anime_emotional`、`music_video`及び`passthrough`です。開始視点、移動軌道、終了視点、被写体周回及び前景視差の指針を後段Plannerへ渡します。

両プロファイルの本文は`prompts/motions/`及び`prompts/cameras/`以下のmanifestにあり、Pythonへ分岐を追加せず拡張できます。Motion又はCameraだけを使用する場合はGGUF推論を行いません。

結合時は、user Commonを最優先として、Unicodeと空白を正規化した後に完全一致するCommon行だけを一件へ縮約します。意味が似ているだけの行は削除しないため、ユーザー指示を類似度判定で失うことはありません。

アニメ年代別スタイルとmotionの`mv_anime_emotional`／`limited_anime`は、共通の作画・接地・口形同期の4行を揃えてあるため、併用してもそれぞれ一度だけ出力します。motionの`mv_anime_emotional`は楽曲に合う全身演技と付属物の追従、cameraの同名プロファイルは1ショットの主軌道、広いアーク移動及び前景視差を加えます。

## 肯定形プロンプトの検証

アニメ年代別スタイル、motionの`mv_anime_emotional`／`limited_anime`及びcameraの`mv_anime_emotional`では、望まない媒体・表情・動作を列挙する代わりに、望む状態と動作の進行を記述します。H3で否定文が必ず逆効果になることや、肯定形で生成が必ず改善することを保証するものではありません。他のプロファイルやユーザー入力の禁止文を機械的に削除する機能ではありません。

目の形・虹彩・瞳孔などのキャラクター固有条件は汎用プロファイルへ固定せず、ユーザープロンプト側で調整します。次は、目の形と弱い輝き、丸眉を肯定形で指定する置換例です。旧行へ追記するのではなく、対応する旧行と差し替えてください。

```markdown
# 共通プロンプト
* <Subject 1>の両目は横長のアーモンド形とし、目尻を目頭より少し高くする。上瞼の外側は目尻へ向かって緩やかに上昇し、虹彩の上部にかかる。歌唱中もこの輪郭と落ち着いた目の開きを保つ。
* <Subject 1>の虹彩は円形を基本とする大きめの金橙色で、上部は上瞼に覆われている。虹彩には琥珀色、黄金色及び淡い黄色の繊細な階調を描き、中央に小さな暗色の縦楕円の瞳孔を配置する。
* <Subject 1>の虹彩に複数の小さな白い反射光と、下側の淡い黄金色の輝きを描く。発光の範囲は虹彩の内側とし、顔と周囲は月光による夜間の露出を保つ。
* <Subject 1>の目尻の縁に細い赤色の化粧を描く。虹彩は金橙色から淡い黄色、瞳孔は暗色、白目は夜間照明を受けた白色として、それぞれの領域と配色を保つ。
* <Subject 1>の眉毛は、髪と同じ淡い金色で塗りつぶした短く太い楕円形とし、左右に一つずつ配置する。長さは片目の横幅の約三分の一とし、全Sceneで位置、大きさ、色及び丸い輪郭を引き継ぐ。
* 時間帯は夜間とし、月の出た濃紺の空の下で、弱い青白い月光が人物と情景を照らす。
```

ユーザー入力は保護されるため、既存の禁止文はプロファイル更新だけでは変わりません。元のSubject・保持分析にも同じ特徴の指示がある場合は整合を確認してください。比較時は参照画像・音声・シード・その他の設定を揃え、まず差分だけを変えて、H3へ渡る最終プロンプトも確認します。

改訂manifestを実行環境へ配置すると、次回のエンハンサ実行でファイルの変更がキャッシュ識別へ反映されます。生成済みの文章・Plan・動画はそのままです。作業用とComfyUI実行用が別フォルダの場合は実行終了後に配置し、エンハンサから後段まで再生成してください。

## 背景の保全

背景密度の変更は、場所や主要な構造物を削除する指定ではありません。元の場所・物体・位置関係をLLMが固定要素として分類し、Pythonが`情景の固定要素: ...`という共通バレットへ原文のまま残します。後段Plannerもこの情報を読み、最初の要求シーンに提示します。

`semantic_guard`は実験的な追加意味監査で、既定はFalseです。8Bでは正しい昼夜変更も拒否する誤検出が確認されたため、通常はFalseを推奨します。固定要素の原文コピーとPlannerへの受け渡しはFalseでも有効です。Trueでは変更行の欠落をLLMで照合し、追加推論と最大2回の意味修復を行いますが、誤検出による停止の可能性があります。

生成された`BACKGROUND`に人物、ポーズ、構図、カメラ又は発声が混入した場合、その行だけを除外します。環境だけの行が一行以上残れば背景密度が指定値を下回っても警告付きで継続し、全行が不適切な場合だけ再試行します。

## ユーザー指示を保護する

人間が最後に確定した指示は`user_prompt`へ接続します。この内容はLLMの分類対象にせず、source拡張後に機械的にマージします。夜間等の確定時間帯と自動背景が矛盾した場合は、自動生成された背景行だけを除外します。

画風と背景を両方`passthrough`にするとGGUFをロードしません。`keep_model_loaded=False`が既定です。モデル、画風、背景、人物動作及びカメラは外部STRING overrideでも変更できます。

詳細は[Prompt Enhancer仕様](../spec/cl_prompt_enhancer_spec.md)を参照してください。
