# CLプロンプト用語辞書仕様

## 1. 目的

本仕様は、`CL Japanese to JSON (GGUF)`の翻訳で小型LLMが反復して未翻訳にする日本語用語を、ユーザーがPythonコードを変更せず決定論的に英語へ置換する外部辞書を定義する。

辞書は一般の機械翻訳器ではない。意味が利用者側で一意に確定している短いプロンプト用語に限定して使用する。

## 2. ファイルと優先順位

辞書は次の順に読み込み、後のファイルに同一`source`があれば前の定義を上書きする。

1. 同梱辞書: `node_japanese_to_json/dictionaries/prompt_terms.csv`
2. 開発用ローカル辞書: `node_japanese_to_json/dictionaries/prompt_terms.user.csv`
3. ComfyUIユーザー辞書: `<ComfyUI user directory>/cl_japanese2json/prompt_terms.csv`

通常の追加・上書きには3を使用する。標準的なComfyUI配置では`ComfyUI/user/cl_japanese2json/prompt_terms.csv`となる。親ディレクトリとファイルは利用者が作成する。ユーザー辞書がない場合は同梱辞書だけを使用する。

開発用ローカル辞書はGitの追跡対象外とし、配布用の同梱辞書を変更せず動作確認したい場合に使用する。

各候補ファイルの存在、更新時刻及びサイズを正規化処理ごとに確認する。追加、変更又は削除を検出すると再読込するため、正常に保存されたCSVはComfyUIを再起動せず次の実行から反映する。

## 3. CSV形式

文字コードはUTF-8又はUTF-8 BOM、改行形式は任意とする。ヘッダーは次の2列と完全一致しなければならない。

```csv
source,target
画面全体,the entire frame
画面,frame
非可読,illegible
```

- `source`: 置換対象の日本語を含む文字列。
- `target`: 日本語を含まない確定済み英語文字列。
- 空行は無視する。
- `source`が`#`で始まる行はコメントとして無視する。
- カンマを含む値は標準CSV規則に従ってダブルクォートで囲む。
- 同一ファイル内で同じ`source`を複数定義してはならない。
- 改行を含むセル、空のセル、不正なヘッダーはエラーとする。

## 4. 適用規則

1. 参照タグとダイレクトスピーチを不透明なプレースホルダへ保護する。
2. 保護後の翻訳入力へ辞書を適用する。
3. 残りの日本語をLLMで翻訳する。
4. LLM応答へ辞書を再適用してから日本語残留を検証する。
5. プレースホルダを元へ戻す。

従って、`<d>...</d>`及び日本語かぎ括弧から保護された台詞内の語句は辞書で変更しない。

複合語を短い語より先に置換するため、全辞書をマージした後に`source`文字数の降順で照合する。例えば`画面全体`は`画面`より先に処理する。CSV上の行順を実行順として使用しない。

置換語が既存のASCII英数字へ隣接する場合は必要なASCII空白を補う。これにより`entire画面`を`entire frame`へ修復する。

## 5. エラーとログ

次は`TranslationError`としてコンパイルを停止する。

- 同梱辞書の欠落。
- CSVの読込失敗又はヘッダー不正。
- 空の`source`又は`target`。
- `source`に日本語がない。
- `target`に日本語が残る。
- 同一ファイル内の`source`重複。

辞書の初回読込又は再読込時は、有効な対応数と読込元をINFOログへ記録する。LLM応答を辞書で修復した場合は、レコードIDと置換した`source`をWARNINGログへ記録する。翻訳入力に対する通常の事前置換は警告しない。

## 6. 運用上の注意

- 語義が文脈で変わる長文、助詞を含む広すぎる断片又は一般動詞を登録しない。
- `target`はH3へそのまま渡せる簡潔なUS Englishとする。
- ユーザー辞書の変更は既存ワークフローの入力ソケット又はウィジェット順を変更しない。
- 問題が解消した汎用語だけをレビュー後に同梱辞書へ昇格し、環境固有の回避策はユーザー辞書へ残す。

同梱辞書にはフレーム位置の固定語に加え、意味の極性を決定論的に維持する`非可読`を収録する。疑似文字を許可する複合語は、画面内文字禁止と矛盾するため同梱しない。
