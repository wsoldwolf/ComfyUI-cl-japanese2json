# CL Load Text File仕様書

## 1. 目的と信頼境界

本書は`CL Load Text File (Drag & Drop)`の詳細仕様を定義する。本ノードはComfyUIのブラウザ画面で任意のローカル場所にあるプレーンテキストを選択又はD&Dし、その内容をSTRINGとして他ノードへ渡す。

本書を当該ノードの正本とする。共通の登録要件は`docs/cl_japanese2json_comfyui_node_spec.md`に従う。

バックエンドはユーザー指定パスを開かない。ブラウザが読み取ったバイト列だけをBase64として受け取り、再検証して復号する。この境界により、`ComfyUI/input`へのコピー、サーバーからの任意パス参照及びパストラバーサルを必要としない。

## 2. ComfyUI登録

| 項目 | 値 |
| --- | --- |
| ノード型 | `CLLoadTextFile` |
| 表示名 | `CL Load Text File (Drag & Drop)` |
| 関数 | `load_text` |
| カテゴリ | `MiniMax H3/Prompt Tools` |
| 出力 | `text: STRING` |
| 出力ノード | False |
| フロントエンド | `web/cl_text_file_loader.js` |

ノード自身は本文プレビューを持たない。必要な場合は通常のSTRINGプレビューノードを接続する。

## 3. ブラウザUI

フロントエンドは次を提供する。

- 非シリアライズの`テキストファイルを選択 / D&D`ボタン。
- ブラウザ標準ファイル選択ダイアログ。
- ノード全体へのドラッグ＆ドロップ。
- 読込成功後のbasename及びファイルサイズ表示。

D&Dに複数ファイルが含まれる場合は先頭だけを読む。選択ダイアログの`accept`には`text/*`及び`.txt`, `.md`, `.markdown`, `.srt`, `.vtt`, `.csv`, `.tsv`, `.json`, `.yaml`, `.yml`, `.log`, `.prompt`を指定する。この指定は選択支援であり、拡張子をバックエンドの信頼条件にはしない。

ブラウザは`File.arrayBuffer()`で原バイト列を読み、`TextDecoder("utf-8", {fatal: true})`でUTF-8妥当性を事前確認する。Base64変換は大きな引数展開を避けるため分割して行う。

16 MiB超過又はUTF-8エラー時はボタンをエラー表示にしてコンソールへ記録し、直前の正常なシリアライズ値を上書きしない。非同期読込には世代番号を持たせ、古い読込完了が後から選択したファイルを上書きしてはならない。ノード削除時は生成した非表示のDOM file inputを削除する。

## 4. シリアライズ入力

Pythonノードのrequired入力は次の順序とする。フロントエンドは通常表示から隠すが、全てワークフローJSONへシリアライズする。

| 名前 | 型 | 既定 | 上限 | 意味 |
| --- | --- | --- | --- | --- |
| `file_name` | STRING | 空 | 1024文字 | ブラウザが渡す表示用ファイル名 |
| `file_base64` | STRING multiline | 空 | 16 MiB相当 | 選択ファイルの原バイト列を表すBase64 |
| `file_signature` | STRING | 空 | 512文字 | サイズ及び更新時刻を含むブラウザメタデータ |

`file_name`は診断用メタデータであり、パスとして開いてはならない。ブラウザのセキュリティモデル上、絶対パスの取得又は保存を要件にしない。`file_signature`はキャッシュ指紋の一部であり、バックエンドはそのJSON内容を信頼又は解釈しない。

## 5. バックエンド復号

Pythonはフロントエンドの事前検証を信頼せず、次を順に検証する。

1. `file_name`が空白だけではない文字列で、NULを含まず、1024文字以下である。
2. `file_base64`が文字列で、16 MiBの原データに対応する最大符号化長以下である。
3. `base64.b64decode(..., validate=True)`でstrictに復号できる。
4. 復号後のバイト数が16 MiB以下である。
5. UTF-8又はUTF-8 BOMとして復号できる。
6. 復号した本文にNULがない。
7. `file_signature`が512文字以下の文字列である。

空ファイルは、空でない`file_name`が設定されていれば空STRINGとして許可する。UTF-8 BOMは出力から除去する。CRLF及び単独CRはLFへ正規化する。その他の本文文字は変更しない。

## 6. 出力とキャッシュ

`load_text()`は1要素tuple`(text,)`を返す。

`IS_CHANGED()`は`file_signature`、`file_name`、`file_base64`をNUL区切りでSHA-256へ入力し、64桁の16進指紋を返す。本文そのものを含めるため、同名、同サイズ及び同更新時刻のファイルでも埋め込み内容が異なればノードを再実行する。

元ファイルはワークフロー実行時に再読込しない。ワークフロー再読込後は埋め込まれたBase64を使用するため、元ファイルを編集した場合は再度選択又はD&Dしなければならない。

## 7. ログ、エラー及びプライバシー

不正なファイル名、Base64、サイズ、UTF-8、NUL又はメタデータは`TextFileLoadError`として処理を停止する。バイナリ判定の自動回避、文字コード推測又は置換文字による復号は行わない。

Python logger名は`cl_textfile`、ユーザー可視ログ接頭辞は`[cl_textfile]`とする。成功ログはANSIシアン色の`[cl_textfile] success:`とし、安全に抽出したbasename、原バイト数及び出力文字数だけを含め、本文と絶対パスを出してはならない。

ファイル本文はBase64としてワークフローJSONへ埋め込まれる。この方式はワークフロー単体での再実行を可能にする一方、JSONサイズを増加させる。機密テキストを含むワークフローを第三者へ共有してはならない。

## 8. 非目標

- バックエンドからの任意パス読込。
- `ComfyUI/input`へのアップロード又はコピー。
- 元ファイルの監視又は自動再読込。
- 本文の編集又はプレビュー。
- UTF-8以外の文字コード自動判定。
- 複数ファイルの結合。
- URL又はネットワークストレージからの取得。

## 9. テスト要件

少なくとも次を自動テストする。

- ノード登録、表示名、入力順序、出力及び`WEB_DIRECTORY`。
- UTF-8 BOM除去、CRLF/CRからLFへの正規化及び空ファイル。
- `file_name`がパスとして開かれないこと。
- Base64、UTF-8、NUL、サイズ及びメタデータ上限の拒否。
- 内容変更でSHA-256キャッシュ指紋が変わること。
- フロントエンドが`File.arrayBuffer()`、D&D及びfatal UTF-8検証を使用すること。
- フロントエンドがupload API及び本文プレビューを使用しないこと。
