# 縮小Markdownコンパイラガイド

`CL Japanese to JSON (GGUF)`は、日本語の縮小Markdownを英語へ翻訳し、MiniMax H3 Full-Reference形式のContex-Loop Plan JSONへ変換します。LLMが担当するのは箇条書き本文の翻訳だけです。ディレクティブ、参照タグ、台詞、SceneとShotの構造、Subject、話者ID、JSON構文はPythonが決定論的に処理します。

## 最小例

```markdown
# サブジェクト
* <Picture 1>を外観参照として使用する人物。

# 保持分析
* <Subject 1> 完全に保持: 顔、髪型、髪色及び衣装を維持する。

# 共通プロンプト
* 明るい昼のオフィス街を鮮やかな2Dアニメ調で描く。

# シーン 8秒
* カメラは人物を正面から捉える。
## ショット
* <Subject 1>が画面中央へ歩く。
## 音響
* 発声: なし
* BGM: なし
```

ディレクティブと`* `は行頭から記述し、同じブロックの途中へ空行を入れないでください。

## ディレクティブ

```text
# サブジェクト
# 保持分析
# 共通プロンプト
# シーン [1～60秒] [継続]
## ショット [開始秒]
## 音響
```

グローバルな3セクションは不要なら省略でき、この順序で最初のSceneより前へ各1回まで置けます。Sceneは1～128個です。

### SceneとShot

- `# シーン 8秒`は8秒の生成単位です。秒数省略時は5秒です。
- `継続`は直前Sceneの映像コンテキストを利用します。最初のSceneでは警告のうえ非継続になります。
- 各Sceneには少なくとも1個の`## ショット`が必要です。
- 最初のShotは開始0秒なので時刻を書きません。
- 2個目以降は`## ショット 4.5秒`のように昇順の開始時刻を書きます。
- `## 音響`は全Shotの後へ1回だけ置きます。
- Scene直下から最初のShotまでのバレットはScene共通の前提です。台詞は置けません。

### コメント

```text
// 行頭コメント
# シーン 5秒 /* 行内コメント */
## ショット
* <Subject 1>が前を向く。 /* メモ */
```

`//`は空白を除く物理行の先頭だけ、`/* ... */`は行内又は複数行で使用できます。ブロックコメントの入れ子、閉じ忘れ、対応しない`*/`、HTMLコメントはエラーです。日本語鉤括弧と`<d>...</d>`内の記号は台詞として保持されます。

## 参照タグ

```text
<Picture 1>～<Picture 9>
<Video 1>～<Video 3>
<Audio 1>～<Audio 3>
<Subject 1>～<Subject 4>
```

タグ名と番号の間にはASCII空白が1個必要です。`# サブジェクト`のバレットが順に`<Subject 1>`、`<Subject 2>`へ対応します。Subject定義は一つのバレットにつき一つです。

SceneのJSONには、そのSceneで実際に使用したSubjectだけを番号順に出力します。未定義Subjectはエラーです。

## 保持分析

```markdown
# 保持分析
* <Subject 1> 完全に保持: 顔、髪型、髪色及び衣装を維持する。
* <Subject 2> 部分的に保持: 衣装を維持し、画風はSceneへ合わせる。
* <Subject 3> 属性転送 -> <Subject 1>: <Picture 2>の照明と質感を転送する。
* <Subject 4> 弱い参照: <Picture 3>の構図と雰囲気だけを参照する。
```

使用できる関係は`完全に保持`、`部分的に保持`、`属性転送`、`弱い参照`です。明示規則のないアクティブSubjectは安全のため完全保持になります。属性転送では転送元と転送先の両方を同じSceneで使用する必要があります。

## 台詞

```markdown
# シーン 6秒
## ショット
* <Subject 1>が「こんにちは」と言う。
## 音響
* 発声: 指定台詞のみ
```

台詞より前の同じバレットへ話者`<Subject N>`を書きます。Pythonが話者ID`(SN)`を自動挿入するため、ユーザーは`(Sx)`を書きません。台詞があるSceneでは`発声: 指定台詞のみ`が必須です。

## Source Vocalによるリップシンク

Contex-LoopのSource Timeline経路では、番号付きAudioではなく専用記法を使用します。

```markdown
# シーン 10秒 継続
## ショット
* <Subject 1>が音楽に合わせて身体を動かす。
* リップシンク: <Subject 1> <- ソースボーカル
## 音響
* 発声: ソースボーカルのみ
* ソース音声: 完全維持
```

間奏やイントロではリップシンク行を省略し、`発声: なし`と`ソース音声: 完全維持`を指定します。フルミックスを`source_timeline`へ、同尺・同起点のボーカルステムを`lip_sync_voice`へ接続してください。ボーカルステムは口形駆動専用で、最終音声へ重ねません。

Source Timelineは番号付きAudio参照、生成台詞、生成BGM、`BGM再利用`、環境音及び効果音と同一Sceneで併用できません。

## 番号付きAudioによるリップシンク

正確な台詞を与える形式:

```markdown
* リップシンク: <Subject 1> <- <Audio 1> 「こんにちは」
## 音響
* 発声: 指定台詞のみ
* BGM: なし
```

Audio区間そのものを発声内容の正本にする形式:

```markdown
* リップシンク: <Subject 1> <- <Audio 1>
## 音響
* 発声: 参照音声のみ
* BGM再利用: <Audio 1> 完全コピー
```

この2方式は同じScene内で混在できません。同じAudioを複数人物へ割り当てることもできません。

## 音響

`## 音響`はSceneローカルの許可リストです。空の音響セクションはエラーで、省略した項目は無効です。

```markdown
## 音響
* 環境音: 遠くの都市環境音。
* 効果音: 衣服の微かな動作音。
* 発声: なし
* BGM: なし
```

既存BGMは`BGM`ではなく`BGM再利用`で指定します。

```text
* BGM再利用: <Audio 1> 完全コピー
* BGM再利用: <Audio 1> 部分コピー 00:20.000-00:30.000
```

同じSceneにはどちらか一つだけを書きます。生成用`BGM`と`BGM再利用`は併用できません。完全コピーはAudio全体とScene長が一致する用途向けです。部分コピーの時間範囲はScene秒数と一致させます。

## UIと出力

主要パラメータは次のとおりです。

| 名前 | 用途 |
| --- | --- |
| `plain_text` | 日本語縮小Markdown |
| `model_name` | 検出済みテキストGGUF |
| `max_tokens` | 翻訳1回の最大生成量 |
| `n_ctx` | コンテキスト長。`0`はGGUF既定 |
| `gpu_layers` | `-1`で全レイヤーGPU、`0`でCPU |
| `keep_model_loaded` | 既定`False`。H3実行前にモデルを解放 |
| `seed` | 翻訳seed。再試行時は決定論的に変更 |
| `retry_max` | 検証再試行数。`0`はなし、`-1`は中断まで継続 |
| `save_debug_output` | `ComfyUI/output/cl_japanese2json_debug/`へ中間情報を保存 |
| `speech_guard` | 保護台詞のない発声らしい文を`strict`又は`warn`で処理 |
| `continuation_context_length` | Contex-Loopのhead-overlapと同じ値を指定 |

出力`json_text`をMiniMax H3 Contex-Loop Planの`plan_json_input`へ接続します。出力は`json.loads()`で再検証済みのJSON文字列です。

長いSubject・保持分析は内部で文単位に分割し、翻訳後に元のバレットへ戻します。それらの各文と、明示的な禁止を含む区間は独立して翻訳し、その他は最大16区間をまとめます。共通プロンプトやShotは、動作と例外・禁止の関係を保つため元のバレット単位で翻訳します。Subjectと保持分析をユーザー側で複数行へ分ける必要はありません。

検出対象の禁止文から英語の否定が脱落した場合は、`lost explicit negation`を記録し、その文だけ既存の`retry_max`内で再翻訳します。正常区間は保持し、上限に達した未解決結果は返しません。これは翻訳の意味全体を保証する検査ではなく、否定の対象や範囲が正しいかは英訳の確認も必要です。`save_debug_output`で元バレット・文番号と応答を追跡できます。外部用語辞書の詳細は[プロンプト用語辞書仕様](spec/cl_prompt_term_dictionary_spec.md)を参照してください。

保護された参照や台詞の欠落・重複を検出すると、該当する未解決区間だけをllama.cppの文法制約（GBNF）付き再試行へ切り替えます。`Using grammar-constrained retry`が切替ログです。構造マーカーと元区間の各保護トークンを必須にすることで、同じコピー失敗を繰り返すことを防ぎます。通常の成功区間には文法制約の追加負荷をかけません。`retry_max`は引き続き有効で、`0`なら再試行しません。生成長上限や翻訳内容の誤りまで保証する仕組みではありません。

参照トークンの意味は要求のメタデータでモデルへ伝え、本文と参照の関係を翻訳させます。特定の人物・物体に依存する翻訳はPythonへ追加していません。ComfyUI同梱バックエンドでは`LlamaGrammar.from_string`が必要で、未対応時に制約を黙って無効化しません。`save_debug_output`では各要求の`transport`と`grammar`も確認できます。

開発時に実GGUFで再現確認する場合は、ComfyUIのPython環境から`tools/check_compiler_translation.py`を使用できます。`--model`、`--source`、`--output-dir`を指定し、必要に応じて`--seeds 1 17 42`を付けてください。英語Markdown、Plan JSON及びデバッグ応答を保存し、動画生成は実行しません。`--batches 13`を指定すると同じ入力・設定で作られる13番目のバッチだけを検証し、部分翻訳と応答を保存します（全体のPlanは生成しません）。小さな否定翻訳の回帰入力は`tests/fixtures/compiler_negation_ja.md`にあります。

厳密な文法とJSON契約は[コンパイラ仕様](spec/cl_japanese2json_spec.md)、ComfyUIノード契約は[ノード実装仕様](spec/cl_japanese2json_comfyui_node_spec.md)を正本とします。
